# 实施项目变更

## 改动前

沿目标路径读取适用规则和模块契约，核对现有实现与测试。简单修复不要求计划文件；跨模块、兼容性或数据迁移风险较高时，先明确边界、验收条件和回退方式。

## 改动中

遵循已确认的模块边界。需要突破边界时先说明取舍，不能只为本次方便引入第二份事实来源或绕过现有接口。缺陷尽可能先建立失败复现，再修复；无法自动测试时保留具体原因及人工验收方式。

## 交付前

- 根据实际差异选择验证：核心逻辑用行为测试，公开接口检查兼容性，构建配置运行构建，迁移检查数据和回退风险。测试和构建不是互相替代品。
- 对受影响的长期知识使用 [文档维护](../seed-doc/SKILL.md)；不因完成一次任务而强制写总结文件。
- 修改验证后再次检查最终差异。报告实际运行的命令、结果、未验证范围和残余风险。
- 已获推送授权时检查远端提交及 CI；否则提交结果供审阅，不擅自发布。不得把本地通过说成远端通过。

项目专用命令由 README、配置或相关模块文档拥有，本 Skill 不维护一份命令副本。发布与迁移是否需要额外确认，按当前用户授权和宿主权限处理。
