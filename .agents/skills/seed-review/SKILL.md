# 审查工程治理

## 审查方式

从具体任务或症状出发，确认范围。只要求审查时输出发现，不修改；已授权修复时修改最小权威位置。

检查入口是否能找到规则、Skill 是否误触发、事实是否重复维护、局部要求是否被错误提升为全局规则、初始化是否仍然干扰普通开发。每条发现附具体文件、影响和可复现例子，不凭篇幅评价好坏。

修正后用对应场景复测，并检查相邻场景是否退化：空项目、单文件工具、小型修复、跨模块变化、初始化后的下一次开发。机械检查通过不代表 Agent 实际遵循；实测了什么就报告什么。

不要因一次偶发问题追加永久规则，不自动从上游模板覆盖项目定制。若规则已被实现或新的架构取代，应删除或收敛旧说明，而不是再加例外。
