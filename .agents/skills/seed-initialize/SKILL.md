# 初始化派生项目

## 初始化流程

1. 检查现有文件与 Git 状态，识别空模板还是已有项目。保留已有实现和用户修改，重复执行不得重置已有选择。
2. 从用户需求提取目标、非目标、交付形态和约束。只问影响当前决策的缺失信息；未知事项明确记录为待定，不臆造技术栈。
3. 提出满足首个目标的最小结构与验证方式。经当前授权实施，不把讨论方案升级为编写业务代码的许可。
4. 原位改写根 README 为项目用途、实际入口、运行和验证方式。按真实需要建立模块 README、子 AGENTS 或设计记录；没有对应事实就不建空目录。
5. 更新根 AGENTS 的项目入口与验证命令，删除仅用于首次初始化的触发提示。初始化 Skill 可以保留供明确再次调用，不再自动询问初始化问题。
6. 检查模板专属说明与链接，删除不适用的模板设计、验证说明；保留需要的通用脚本时确认它仍适用于新项目。不能整批删除未知用户文件。
7. 运行实际可执行检查；如果尚无业务代码，明确只验证了基础结构，不能声称功能可用。

## 退出条件

项目入口已描述真实目标和已有事实；下一项已授权工作能开始；未决事项及验证缺口清楚；普通任务不会再次触发初始化。无需等所有功能完成，不创建额外状态机或长期问卷。

新项目若采用不同测试体系，应接入相应的真实检查，不能只运行模板检查器就称为工程验证。既有项目只做增量接入，不为模板布局重建目录。
