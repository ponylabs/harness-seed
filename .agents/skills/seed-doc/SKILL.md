# 维护项目知识

## 先判断知识变化

读取适用 AGENTS、目标文档、相关源码与测试。确认读者需要解决的问题以及当前事实来源；已实现、计划和未验证必须区分。只读审查不隐含修改许可。

## 决定归属

- 根 AGENTS：全仓长期开发约束与导航。
- 子 AGENTS：范围内独有的开发约束，不复制父规则。
- 根 README：项目用途、快速开始和深入阅读入口。
- 模块 README：该模块职责、公开入口、配置与使用限制。
- 架构或决策记录：跨模块关系及有长期价值的取舍；存在实际需求再建立。
- 配置、源码与生成器：可执行事实与派生内容的源头；不要手工复制生成清单。

同一事实指定主要维护位置，其他地方用精确链接或必要的简短使用提醒。不把“源码当前如此”当成修改业务约束的授权。

## 更新流程

1. 优先原位修订现有文档，同时删除已失效的说明；不在末尾不断堆“本次更新”。
2. 新建文件前回答：服务谁、现有文档为什么不合适、什么变更会触发更新。没有答案就不新增。
3. 根据读者和用途组织最少必要章节，不要求所有文档统一套摘要、目录和结论。
4. 使用 [表达标准](../seed-prose/SKILL.md) 检查语义完整与冗余。
5. 核实命令、配置、默认值、失败行为。能安全执行的例子实际执行；缺环境时标明未验证，不根据邻近项目类推。
6. 检查新增、移动、删除造成的链接影响；运行当前项目适用的文档检查并审阅最终差异。

## 完成条件

事实有明确归属，内容与当前实现或已确认设计一致，失效内容已处理，验证范围透明。允许结论为“无需文档修改”。模板不强制双语、文档站、固定行数或定期全仓重写。
