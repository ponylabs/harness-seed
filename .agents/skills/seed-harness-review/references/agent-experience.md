# Agent 使用体验

目标是减少完成任务的总工作量，同时保留可靠决策所需的信息，不是单独追求少几个 token。

## 最小可用入口

1. 起始上下文交代目的、可用动作和关键限制。详细知识按需发现和读取，并给出真实、明确的入口。
2. 权限、破坏性影响、前置条件与验证要求必须在执行前可见，不能藏在事后结果或未提示的深层文件里。
3. 工具返回适量的命中内容及稳定标识、路径和必要的相邻上下文。截断要说明遗漏范围和继续读取方法；空结果应能区分无匹配、权限不足与查询失败。
4. 同一个事实只由一处维护。系统入口、工具总描述和参数说明不要重复整段规则；参数特有约束写在该参数旁。
5. 说明可观察行为而非内部实现；省略参数名已经清楚表达、不会影响选择的常识。不能借精简删掉异常语义和边界。

## 验证

从几乎没有背景的新会话完成一个代表性任务：能否找到正确入口、理解动作后果、取回遗漏内容、识别失败并验证结果？比较首轮上下文、后续检索和重试的总成本。少了入口但多次猜路径，不算改善。只有确认宿主支持时才依赖自动发现；保留显式文件入口。
