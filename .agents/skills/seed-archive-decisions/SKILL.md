# 维护决策的有效性

按未来决策价值判断，不按年龄、篇幅或“已实现”批量归档。没有这些记录的项目不必为使用本 Skill 新建目录。

## 判断

- 新决策先查同一问题域的已有记录。完全替代时标明旧记录不再有效；部分替代则保留独有约束，互链具体边界。
- 已实现但仍解释取舍、失败方案、兼容性、持久化、安全或容易重犯的错误，保留其长期理由。
- 只有机械操作或琐碎界面调整、没有剩余决策价值的记录可以考虑删除；遵守仓库和用户对删除的授权，不直接批量清空。
- 有历史价值但不再约束当前实现的记录归档。仍在提议中的方案不能伪装已实现而归档；放弃就准确标记拒绝或撤回。
- 被拒绝的方案仅在仍能阻止有吸引力的错误方向时长期保留，不以记录数量制造知识负担。

## 操作

先读项目现有状态和归档约定，不引入固定目录、双语三件套或哈希协议。更新活跃入口、替代关系及指向已移动记录的链接，检查是否遗漏部分有效内容。

已冻结历史正文不为迎合当前实现而现代化，也不随手修复历史语境的外链；在活跃入口说明后继事实。项目确需更正历史错误时按明确流程处理，不篡改原先决策。

给出处理列表、理由和存在争议的边界。无需整理就不改，不设每次必须归档多少篇的配额。
