# 界面与响应式行为

先读取现有组件、样式令牌及交互约定，确定支持的视口、主题、输入方式和平台。优先沿用已有模式，不带入其他项目的字体、颜色、框架和固定最小宽度。

## 项目视觉契约

Web 项目先读取或按 [文档契约](../../../docs/AGENTS.md) 建立 `docs/web-styling.md` 与 `docs/ui-radius.md`，以实际组件、样式 token 和已确认设计为依据。前者拥有布局、排版、颜色、间距、主题、响应式与组件复用；后者拥有圆角 token、组件映射、嵌套关系及例外。实现变化同次更新唯一拥有者，其他页引用，不复制数值。没有设计依据时先确认影响一致性的关键选择；不套用 DeepSeek 的值。无 Web 场景不建这些文件。

## 布局与内容

- 在约定最小视口仍能完成主要任务，无意外重叠、裁切和整页横向滚动。先重新分配空间和换行，再考虑截断、图标或更多菜单。
- 不通过全局隐藏溢出、缩小所有字体、压缩点击目标掩盖布局问题；不能把关键状态和操作挤没。
- 标题允许换行，必要时操作另起一行。截断内容要有可访问的完整入口，错误和区分对象的关键信息不能仅剩省略号。
- 图标需有清楚语义和可访问名称；悬停解释不能成为唯一的操作路径。
- 对齐按容器轴线、基线和总偏移检查。复杂区域先定布局轴，再调局部间距；安全区和原生标题栏沿现有平台约定，不为局部问题改全局偏移。

## 输入与焦点

悬停能力与屏幕宽度分别判断。触摸设备不能留下粘滞悬停态；混合设备处理真实指针类型。选中、展开、焦点是独立状态，键盘也能到达同样的功能。

响应式切换避免无必要的卸载重建，保持输入和焦点；元素确实隐藏时转移到合理目标，不随意弹出软键盘。辅助性 tooltip 可按输入能力调整，但实质说明必须有点击或键盘入口。不要用 UA 猜布局或把有鼠标等同有键盘。移动端自动缩放等问题在目标平台验证后局部处理，不变成所有设备的固定字号要求。

## 状态和反馈

成功/失败反馈要在临时面板关闭后仍可理解。已有内容的查询或刷新失败保留原内容，明确标示过期/失败并提供重试，不用空白或初始失败页替换仍有价值的信息。删除失败保留原对象；与当前内容相关的失败留在内容旁，初始加载失败则提供明确的页面状态和重试。错误简短、可行动，不泄露内部细节，不破坏布局。

区分状态所有者与渲染所有者：跨面板/路由仍有效的操作状态由合适的长期所有者维护，短期渲染订阅随视图清理。面板关闭后不让完成回调写入已销毁视图，不重复订阅或重复提示；异步结果应核对当前对象和请求身份，避免旧响应覆盖新状态。

采用一致的加载模式，避免大量互相竞争的指示器。菜单能通过外部点击和 Escape 退出，放置在视口内，翻转策略稳定，避免被裁切或遮挡；滚动条不得覆盖内容。

## 验证

覆盖目标窄/宽视口、支持的明暗主题、长内容、空/加载/失败状态、键盘及触摸。对可见变化检查实际渲染，而不仅是样式值。需要演示证据时使用 [界面证据参考](references/ui-evidence.md)。项目约定需要设计评审时按现有流程申请，不凭空增加审批角色。
