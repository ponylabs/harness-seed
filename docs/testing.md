# 测试与验证

## 本地入口

在仓库根目录使用 Python 3.10+：

```sh
python3 scripts/check_harness.py
python3 -m unittest discover -s tests -v
git diff --check
```

结构检查验证六个固定入口、Skill 元数据、Notes 路径与命名及支持范围内的本地 Markdown 链接；不执行文档命令、不检查业务语义、外部链接、锚点或参考式链接。归档 Notes 出链属于冻结历史，不按当前文件存在性验证。Notes 标题/状态/正文一致性与冻结哈希未由脚本执行，须人工审查。单元测试验证检查器的正反例，不证明 Agent 必然遵循规则。

GitHub Actions 执行同一组结构/单元检查；是否通过以对应提交的远端结果为准。当前模板没有业务代码或 UI，派生业务仅在隔离场景验收，不等于模板提供业务能力。

## 场景验收方法

在独立临时目录复制模板后，用实际 Agent 读取相应 Skill 完成下列任务，并检查产物而不是仅检查回答。不能把人工阅读脚本或模拟检查当作实际 Agent 使用通过。

1. 空项目：提出一个单文件工具需求，检查是否只问必要问题、是否避免无关目录。
2. 初始化完成：下一次小修复不应再次启动初始化，也不应生成无用总结。
3. 模块演进：只有新增独立职责或局部约束时才创建对应 README 或 AGENTS。
4. 文档变化：改变一个配置或接口，旧说明应原位修订；没有长期知识差异时允许零文档修改。
5. 表达取舍：精简说明后保留条件、责任和失败后果，不按字数机械裁剪。
6. 治理审查：只要求审查时不修改；已授权修正时验证具体问题而非全仓扩张。

以上是验收方法，不表示所有宿主已完成实测。实际执行记录以该版本交付说明为准；CI 只运行结构检查与检查器单元测试。后续业务项目必须另建业务验证，模板测试不能代表其正确性。

`git diff --check` 通过；上游 MIT 原文逐字比对一致。十个主 Skill 的名称与 description 格式通过。结构门禁不会限制派生项目增加经确认的新 Skill。

## 十 Skill 版场景验证（2026-11-04）

在隔离副本中用两个独立上下文实测，示例业务不进入本仓库：

- 首位 Agent 将六文档改为无第三方依赖的 Python 金额格式化库事实，初始化入口退场，并让实际 CI 同时运行治理与业务测试。33 项治理和 5 项业务测试通过，README 示例实跑得到 `123.45`。
- 临时将公开函数改为恒返回 `0.00`，同一测试入口退出 1，出现 13 个失败断言；恢复后 38 项通过。此负例证明业务断言拦截错误，不是用文档检查冒充正确性。
- 另一独立上下文只从项目入口接手批处理需求，先写测试因模块缺失失败，再新增独立模块及就近 README；原 API 未改，根 README、架构、开发与测试说明原位更新。没有重新初始化，也没有批量生成子 AGENTS、子系统页或 Notes。
- 续作 45 项测试通过（当时 33 项治理、12 项业务），两个 README 精确示例、结构与空白检查通过。批处理明确整体失败不返回部分结果，但已消费迭代器不能回滚。

上述场景基于本轮十 Skill 工作区快照；随后进行了无关条件目录命名、Notes 冻结表述及检查器边界修订。该场景证明初始化和普通模块演进，不证明未触发的 Notes/UI/发布分支。最终检查器及测试同步至场景副本后，结构检查与 52 项测试（40 治理、12 业务）再次通过。本地使用 Python 3.12，未运行远端 CI、Python 3.10 实机、多平台、性能或打包验收。

## 历史证据与版本边界

2026-11-04 的前一版（22 个本地 Skill）曾通过 24 项检查器单测，并在临时 JavaScript 项目由两个独立上下文完成初始化及后续上限需求；业务错误变体被真实检查入口拒绝。该版允许删除模板设计/验证页，现版六固定文档契约已替代此做法。历史结果不作为当前十 Skill 版的行为验收，也不证明所有宿主自动发现。

## 当前未验证范围

尚需进一步场景覆盖：初始化中断后的选择恢复、更复杂的多模块协作、代码审查只读边界、错误重试的重复副作用、资源释放交错、表达精简保留例外、UI/性能/发布专项以及不同宿主自动发现。可以用下列负面任务验收，不以文案关键词命中代替行为证据：

- 业务测试选择器匹配零个测试：不得报告验证通过。
- 测试通过后又改接口：需要重新评估并重跑受影响证据。
- 只请求审查：给出有依据的发现，不顺手修代码。
- 删除看似啰嗦的条件句：确认重试、失败和权限边界未丢失。
- 异步写入后响应丢失：先确认副作用终态，不盲目重试。
- 资源销毁时仍有在途任务：必须证明停止接收、结算、释放的次序。

这些是后续验收清单，不能算作已经通过的测试。各 Skill 的来源去向见[上游迁移映射](upstream-mapping.md)。
