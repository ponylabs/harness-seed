# 架构与边界

Harness Seed 是可复用的项目起点，沿用 DeepSeek Harness 的知识分工和专项方法，去除产品专属假设。它不保证模型始终读取规则，也不保证项目仅靠持续开发就自动形成完整治理能力。

## 知识归属

根 AGENTS 放短规则与任务入口；子 AGENTS 放该范围独有的要求。README、架构和模块说明承载当前项目事实；Skill 承载可复用的工作方法。Notes 的格式与生命周期由其 [README](../.agents/notes/README.md) 和局部规则拥有，归档 Skill 执行操作而不重复定义规范。

一个事实有一个主要维护位置，其他位置链接。核实实际实现和既定契约，发现冲突时不能擅自以代码替代需求。当前事实原位更新；历史原因进入适当记录，过时内容退出，不追加聊天或实施流水。

## 模板与派生项目

六个固定文档是模板的稳定入口，不是固定业务架构。初始化将本仓库的事实替换为真实项目事实，保留适用的方法、文档契约和来源许可；条件文档只在出现实际职责时创建。

初始化负责首次交接，不负责日常治理调度。它检查本地脚本、CI 与文档是否说明同一套真实验证；业务项目不能只运行模板检查后宣称业务通过。中断时只保存下一会话需要的目标、已确认选择和验证缺口，完成后收敛。

## 方法分工

文档维护处理事实归属和文档操作；表达标准处理语义完整性；代码审查同时评估代码、规则、检查、Notes 和可见文字的必要性与正确性。Agent 体验方法用于设计 Skill、上下文、工作流和模型可见工具，不是治理总调度器。

性能、简化、响应式、录制、升级和 PR 等方法具有各自的任务入口，按相关任务发现，不藏在不匹配的检查入口下。扩展翻译流程仅由用户按名称调用。根 [AGENTS](../AGENTS.md) 提供导航；宿主仍决定如何发现和加载 Skill。

迁移按 [上游映射](upstream-mapping.md) 区分继承的方法、通用适配、模板专有能力和不适用的产品流程。不以固定 Skill 数量为目标，不增设统一治理审查层。

## 检查与依赖

`scripts/check_harness.py` 使用 Python 标准库检查文档入口、Skill 元数据、Notes 契约与归档冻结，以及支持范围内的 Markdown 文件链接。测试在临时目录构造正反例；CI 执行同一入口。准确覆盖及命令见 [测试说明](testing.md)。

检查器不证明文字事实正确、业务行为正确或模型实际加载了规则。Agent 行为需要独立场景验证；本地检查不证明远端 CI 已通过，工作流存在也不等于分支保护生效。

模板不运行业务服务，不持有业务数据，没有数据库或 UI。派生项目按实际技术栈建立测试、构建和必要的专项检查；通用模板不复制上游整个产品 CI。
