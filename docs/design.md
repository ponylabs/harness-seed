# 设计与边界

Harness Seed 是可复用的工程治理起点。它学习成熟项目的具体判断方法，去除产品专属假设，不承诺消除所有上下文丢失、架构漂移或业务错误。

## 知识归属

根 AGENTS 是短入口和全局约束，子 AGENTS 仅记录范围内独有的规则。README、架构与模块说明承载项目实际知识；Skill 承载可重复使用的方法、失败分支和证据要求。专题参考按风险加载，不把全量资料塞入每次会话。

先从现有事实来源核实，不把实现与业务约束冲突简单解释为“以代码为准”。一个事实有主要维护位置；使用处可以保留影响安全操作的短提醒。更新优先原位修订，过时内容退出，不追加任务流水。

## 模板与派生项目

本仓库的 README、设计、迁移和验证说明描述模板本身。派生项目初始化后，入口应反映业务目标和实际验证能力，不保留无关教程。没有独立职责就不建立模块 README，没有局部规则就不建立子 AGENTS；不强制前后端、数据库或文档站目录。

初始化不是填完文档：需要明确哪些行为已有证据，哪些检查仍缺失；同步检查实际本地命令、CI 与说明。业务检查失败不能被模板检查成功掩盖。尚无 CI 或业务代码时如实报告，不为了看起来完整创建虚假门禁。

中断或跨会话接手只持久化继续工作需要的目标、已确认选择、剩余动作和验证缺口，放到已有、可发现的位置；完成后收敛，不制造永久聊天日志。

## Skill 演进

文档维护管理分类、归属、生命周期及事实核验；表达标准管理文字完整性。代码审查检查行为及风险，治理审查检查 Harness 本身，不混为一谈。验证 Skill 负责证据选择和失效判断，专项错误、测试、UI、性能与发布方法只在涉及相应风险时读取。

迁移以[固定上游版本与逐项映射](upstream-mapping.md)为依据。先保留成熟的决策密度，再替换专属事实；不通过任意增加页数证明成熟，也不为保持短小删去关键失败分支。每次更新应检验实际使用场景，不能只检查文件存在。

## 自动检查的能力范围

基础检查器验证入口、Skill 元数据和支持范围内的本地文件链接。它不验证业务正确性、文字语义、全部 Markdown 形式或模型调用。单元测试证明的是检查器的行为；真实 Agent 场景验证另行记录，不能互相替代。

CI 执行检查不等于平台已禁止失败提交合并。权限、分支保护、凭据和部署配置不随克隆自动生效。派生项目需建立自己真实的测试、构建及适用的架构检查，不能把模板测试当作业务验收。
