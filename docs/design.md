# 设计与边界

Harness Seed 把长期约束、项目事实和可复用方法分开。它提供一个能检查、能调整的治理起点，而非承诺消除所有上下文丢失、架构漂移或业务错误。

## 知识如何演进

根 AGENTS 是短入口；Skill 按任务加载；模块独立职责形成后才建立 README，存在局部规则才建立子 AGENTS。设计变化应修订已有事实来源，必要时增加决策记录。没有真实内容时，不建立空章节或目录。

模板自身的 README、设计与验证文档用于维护本模板。派生项目初始化时将入口替换为真实项目内容，移除不适用的模板专属说明；五个通用 Skill 可保留并按实际需求调整。初始化完成后不再由普通任务自动触发初始化。

## 为什么拆开文档与表达 Skill

文档维护处理事实归属、文件职责和生命周期；表达标准处理句段中不能丢失的行为语义。分开后，代码注释可以只使用表达标准，而文档结构调整不必读取所有写作细节。开发变更 Skill 仅连接项目上下文、验证与知识同步，不复制编码教程。

## 自动检查范围

检查器验证根入口、Skill 元数据以及本地文件链接，失效时返回非零。测试包括正常仓库、缺入口、错误元数据、断链和路径越界等情况。它不解释业务、不运行 Markdown 命令、不检查外部 URL 和锚点，也不证明 Agent 自动发现 Skill。

CI 可执行检查不等于禁止合并；平台分支保护和凭据设置需由所有者按权限配置。模板不包含自动推送、自动发布、密钥和生产连接。后续项目必须按技术栈补足真实业务测试、构建与适用的架构检查。
